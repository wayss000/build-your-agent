# P00 课程介绍｜写一个自己的 Agent

这套课程有一个具体任务，让自己写的 Agent 查看一个项目，读懂目录和关键文件，再生成一份项目说明。

听起来不复杂。但拆开以后，就会遇到几个值得动手弄清楚的问题。模型怎么知道目录里有什么？谁来执行读取文件的命令？读完一个文件还不够，它怎么继续？什么时候算完成？

我们会从一个终端程序开始，把这条链路一步步接起来。

如果你用过 Codex，或者关注过 Hermes、OpenClaw，可能已经见过 Agent 读取文件、执行命令、根据结果继续工作的过程。看着它做事，和能解释它为什么这样做，中间还有一段距离。这套课程想帮你走过这一段。

模型返回一条命令，并不会让电脑自动执行它。需要有程序接住这条命令，检查参数，调用工具，再把执行结果交回模型。模型看到结果，才有机会调整下一步。

这里就出现了我们要写的 loop Agent。loop 是循环，一轮里调用模型，需要工具时就执行工具，再带着结果进入下一轮，直到得到回答或触发停止条件。

名字可以晚一点熟悉，执行过程要亲手走一遍。

起点很小。你在终端输入一句话，程序原样回显。等连续输入和退出都跑通，再接入模型，让回复真正来自模型接口。随后把配置独立出来，加上日志，看看每次输入究竟经历了什么。

到 Bash 工具这一课，我们先直接运行一条命令，检查正常输出、错误输出和退出码。等这一层清楚了，再让模型生成工具调用参数。模型负责提出调用请求，Python 负责实际执行，日志把两边的过程串起来。

工具执行之后怎么办？这是 Agent 循环这一课要接上的部分。把结果放回消息中，再请求模型。它可能已经能回答，也可能还需要读另一个文件。我们会给循环设置上限，避免任务一直转下去。

回到生成项目说明这个任务，循环就有了用处。Agent 可以先查看目录，再读取 README 和依赖配置，必要时继续查看入口文件，依据实际内容整理说明。你需要核对它的结论，看看启动命令有没有依据，缺失的信息有没有被它猜出来。

模型也会犯错，命令可能失败，接口可能超时。学习时这些都可能发生。遇到错误，先找到对应的日志，看清失败发生在请求模型、解析参数，还是执行工具这一步。能定位问题，是这套课程的重要成果。

学到这里，你会有一个自己能读懂、能修改的最小 Agent。也可以顺着一次用户输入，指出模型请求在哪里发出、工具在哪里执行、结果在哪里回传。

有了这条线，再看 Hermes 的源码就更容易找到入口。我们会以它为例，对照循环和工具机制，看看真实项目怎样处理这些问题，以及哪些设计值得借鉴。其他开源项目也可以沿着同一条线去看。

后面的课程会围绕持续协作展开。多轮对话保留当前会话的背景，Skill 保存可以复用的任务方法，会话压缩整理过长的历史，长期记忆保存用户明确希望记住的信息。这几种能力各有用途，后续会分开实现和讨论。

目前，教学分支已经开发到 Agent 循环。Skill、压缩和记忆属于后续计划，会根据反馈和开发时间继续推进。Server 部署也会聊，但只讨论思路。先把个人电脑上的 Agent 做到能用、能理解。

开始前，你需要能读懂简单的 Python，知道变量、函数、循环和异常的大概用法。不要求有 Agent 开发经验。模型接口需要自己的配置，调用可能产生费用；Bash 会实际执行命令，练习时请使用可信、没有敏感信息的目录。

课程代码放在 [Build Your Agent](https://github.com/wayss000/build-your-agent) 仓库。`study_step` 分支按教学顺序开发，每个有代码变化的章节都有一个 tag。你可以停在某一课运行，也可以对照前后两个版本，看看这一步究竟增加了什么。具体命令见 [仓库使用说明](../../README.md)。

视频用来讲思路和展示过程，文章供你回头阅读，代码用来动手验证。建议每课先跑通，再改一点。修改回显文字、换一个问题、让 Bash 执行一条会失败的命令，看看结果和自己预想的是否一致。

从 [环境准备](../user_docs/P01_环境准备.md) 开始就好。等你回头再看生成项目说明这个任务，目录是怎么读到的、结果是怎么传回去的、循环是怎么停下来的，都能在自己写的程序里找到。
