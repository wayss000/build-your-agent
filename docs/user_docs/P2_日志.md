# 记录日志

> 状态：已实现；当前使用自定义 `log_event()`，而非 `log.info()`。

## 本章开发目标

让一次请求的输入、执行过程和结果可以通过日志追踪。

## 实现步骤

1. 在 `src/log_event.py` 中集中定义日志函数，自动创建 `logs` 目录。
2. 追加写入 `logs/app.log`，每条记录包含时间、请求 ID、模块和事件名。
3. CLI 使用 `uuid4().hex` 为每次输入生成请求 ID，同一次请求始终复用它。
4. 用 `LogEvent` 枚举统一事件名称，先记录 `INPUT_RECEIVED` 和 `RESULT_RETURNED`。
5. 接入模型与工具后，再记录模型请求、响应、工具开始和工具结果。
6. 失败记录 `RESULT_FAILED`；用 `perf_counter()` 统计请求耗时。

## 运行方式

运行 `python3 src/main.py` 并提交一条输入，再查看 `logs/app.log`。
当前版本可能因模型配置缺失而失败，此时也应记录输入和失败事件。

## 验收检查点

1. 日志文件自动创建，多次请求追加记录而不覆盖。
2. 同一次请求的事件 ID 相同，不同请求的 ID 不同。
3. 中文和结构化结果可读；不要把认证头或密钥写入日志。

## 本章边界

本章不增加日志平台、轮转或并发日志服务；日志含对话内容，分享前检查敏感信息。
